# Changelog

All notable changes to idef0-rs are recorded here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versioning follows the
policy in [docs/architecture.md §16](docs/architecture.md#16-release-and-versioning-sr-54).

## [Unreleased]

### Added
- Web app scaffold (roadmap M7.1; architecture §5.1, §13): `idef0-wasm` is now a Leptos 0.8 CSR app built with Trunk.
  - **State:** `Doc` (model, rev, undo history) and `EditorState` (the diagram on screen) are held as signals. The bundled dogfood model's A0 is drawn from `idef0-layout`'s Scene and SVG.
  - **Running it:** `trunk serve` in `crates/idef0-wasm`.
  - **CI:** the `wasm32 build` job runs `trunk build --release --locked` and reports the gzipped bundle size against NFR-WASM-01's 2.5 MB limit (340 KB today).
  - **Dependency policy:** `deny.toml` allows BSL-1.0 for `xxhash-rust` (via `leptos` → `server_fn`) and ignores RUSTSEC-2024-0436 (`paste` unmaintained, via `leptos`). Both are recorded in architecture §17.1.
- Decomposition and calls (roadmap M1.6; metamodel §7, §11; FR-EDIT-09, -18, FR-CALL-01..04, -07, -09, -12, -13, FR-BAL-01, FR-DIAG-09):
  - **Commands:** `Decompose` creates an empty child (working, derived title); it is rejected on callers, environment boxes and decomposed boxes. `SetCall` replaces a box's one call, and is rejected on decomposed, top and environment boxes and on uncallable local targets. `ClearCall` removes a call.
  - **`idef0_core::calls`:** call labels (`A5.2`, `SEC/A2.1`, alternatives with `|`, unresolved keys as written) and the Used At reverse index across the models given.
  - **`idef0_core::balance::stubs`:** the parent ICOMs a child does not wire yet.
  - **`Model::box_nodes`:** the node each box key details.
  - **Diagram form:** the USED AT field lists the diagram's callers, and A0's CONTEXT shows A-1 when there is one (FR-DIAG-09). The `valid-constructs@A0` SVG snapshot changes accordingly.
- Commands, patches and undo (roadmap M1.5; metamodel §13; FR-EDIT-01..08, -10, -11, -13, -15, -17, -19, -20). `idef0_core::command::apply` is a pure function from a model, a `Command` and an `Env` (the key minter) to a new model and a `Patch`. A patch holds forward and inverse ops (one diagram, concept or the metadata each) and a `RenameMap` (nodes, ports, arrow ids, box keys).
  - Commands: `AddBox`, `RenameBox`, `MoveBox`, `DeleteBox` (the §13.1 cascade), `DeleteDiagram`, `AddArrow`, `DeleteArrow`, `Retarget`, `ReorderPorts` (re-coding the child boundary atomically, with vanished codes becoming `[Sk]` tunnels), `SetDescription`, `SetStatus` and `Paste` (with `copy`, fresh keys).
  - Every patch applies the major and minor status rules and retires removed keys. It rewrites free-text node references in their written style. A command that would add an `E-*` finding is rejected.
  - `apply_all` makes a compound change into one patch. `history::History` keeps one undo stack per model, with navigation to the change or its nearest surviving ancestor and selection repair.
- SVG rendering (roadmap M4.5; layout §14.1, §14.4; FR-LAYOUT-20): `idef0_layout::scene::layout` builds the Scene in su. It holds the frame, the boxes (wrapped titles, corner labels per theme, shadow and DRE for decomposed boxes), the arrows with arrowheads, and the diagram form (working band with author, project, date, status marks and a CONTEXT sketch; identification band with node, title and C-number). `idef0_layout::svg::render` writes deterministic SVG with integer coordinates and `data-key` on every element. The first real CLI command, `idef0 render MODEL [NODE] [--theme] [--out]`, writes it, with the cli §4 exit codes. There are SVG snapshots of every fixture diagram. Frame order now gives the branches of a fork from one boundary port a single shared entry (dogfood crossings 29 → 27, baseline lowered). The ADR 0002 re-check passes: full layout plus SVG of `dense-7x40` takes 1.74 ms p95 on wasm32.
- Track assignment (roadmap M4.4; layout §7; SR-41): `idef0_layout::tracks::assign` puts every channel run on a track. It uses hard VCG edges, dogleg splits that break hard cycles, soft barycenter edges, the constrained left-edge algorithm and sifting on exact crossing counts. It returns the final polylines (`Wiring`) and the tracks per channel, which size the §5.2 gaps; a channel keeps the previous iteration's assignment when a new one needs more tracks and the old one is still feasible. `layout_routes` now returns `Routed` (placement, routing, wiring). Crossings are recorded in `fixtures/layout/baselines/crossings.json` and must not rise. A property test checks the final polylines of generated diagrams: VCG respected, tracks ≥ density, no collinear overlaps, fillet-length segments, deterministic. Role-shift frame entries now sit on the margin's track coordinates and run straight along it (layout §6.3); the template snapshot for `boundary-dog-leg` changed accordingly, and every template snapshot now also lists the wired polylines and tracks.
- Global routing (roadmap M4.3): `idef0_layout::route` routes every edge (plain arrows, fork branches, join leaves, call arrows) by its §6.2 template class, FIPS feedback shapes included (control "up and over", input and mechanism "down and under"). It has the §6.3 cost and rejections, the §6.4 order with up to three rip-up passes, and frame order by ICOM code with distinct, in-frame entries (FR-LAYOUT-22). `layout_routes` runs it inside the §5.2 placement iteration, freezing the channel assignment after iteration 1. There is one template fixture per class in `fixtures/layout/templates/`, with snapshots, and a property test checks generated diagrams: orthogonal, on the lattice, inside the frame, no box-interior hits, nothing forced, deterministic. Layout §6 now states the self-mechanism loop, the role-shift and frame-order dog-legs, frame-entry spacing, the own-box keep-out exemption and center-line channel runs.
- Staircase placement (roadmap M4.2): `idef0_layout::place` with §5.1 gaps (inner `2·clear + max(1, d)·pitch`, margins with label allowance, all on the lattice), the keep-out footprint (shadow and DRE), and the §5.2 iteration driver (gaps only grow, at most 3 routed iterations, then `L-LAYOUT-OVERFLOW` with `reason=iterations`), taking the router as a callback for M4.3/M4.4. `box_plans` and `port_counts` read a diagram.
- Box sizing and ports (roadmap M4.1): `idef0_layout::metrics` (the §3.2 table, `validate()` reporting `E-METRICS`), `text` (`TextMetric::Mono`; `Serif` arrives with the classic theme, M5.5), `size` (§4.2 title wrap at most 3 lines, never truncated; §4.1 box size) and `ports` (§4.4 half-down lattice offsets; the call port is rightmost on the bottom).
- Layout spike (roadmap M4.0): `idef0_layout::spike` prototype (sizing, staircase, global routing, Auto-Arrange step 1), bench fixtures `fixtures/bench/{dense-7x40,arrange-worst-7}.idef0`, the `scripts/layout-spike` harness and the informative `layout-spike` workflow. [ADR 0002](docs/adr/0002-layout-budgets-and-worker.md): layout runs on the main thread; the layout budgets stand; Auto-Arrange stays in the Web Worker.
- `.idef0` parser (roadmap M2.1): `idef0_core::dsl` with a winnow lexer, a lossless CST, a recovering parser (at most 100 errors) and lowering to `Model` plus a `SpanMap`. It derives missing keys, assigns omitted ranks, fills the A-1 lineage box, resolves local node-number call targets and quoted labels, and reports `E-PARSE-*`, `E-VERSION-*`, `E-LIMIT-01`, `L-FMT-01`, `E-ID-01/03/05`, `E-NODE-01/02`, `E-CALL-01` and `E-NOTE-01`. New fixtures: `fixtures/valid/`, `fixtures/invalid/<code>/`, `fixtures/lint/L-FMT-01/`, with diagnostics snapshots.
- Identity (roadmap M1.4; D6, D14): `idef0_core::identity` implements the slug rule (NFKD via the new `unicode-normalization` dependency), the `KeyMinter` trait with `SlugMinter` (lowest free `-2`, `-3` suffix, retired keys count as taken) and structural arrow ids (`A0:1O1->2I1#0`, `->*`, `*->`, `/i`). Diagnostics now name edges by `ArrowId`. The ids of the JSON fixtures are pinned in `.ids` files generated by an independent reference implementation.
- Core type check (roadmap M1.3): `idef0_core::typecheck` reports `E-ID-02`, `E-ID-04`, `E-NODE-02`, `E-NODE-03`, `E-TYPE-01`..`05`, `E-CALL-02` and `E-NOTE-01`; `idef0_core::diag` holds `Diagnostic` and the core E-code registry, kept equal to metamodel §18 by a test. All 144 cells of the arrow-typing table are tested.
- Model types and JSON (roadmap M1.2): `idef0_core::model` (`Model`, `Meta`, `Concept`, `Diagram`, `FunctionBox`, plain/fork/join `Arrow`, `Endpoint`, key-based `CallArrow`, `ModelNote`) and `idef0_core::text` (`NonEmptyString`, box/concept/arrow keys, `Description` with provenance, `CNumber`, `LangTag`). Diagram kind and DRE are derived. JSON round-trip fixtures in `crates/idef0-core/tests/model_json/`; a `compile_fail` doctest shows a box needs a `NonEmptyString` name.
- Node and port references (roadmap M1.1; FR-ID-01, FR-ID-07, FR-ID-08): `idef0_core::id` parses and displays `NodeId`, `NodeRef` and `PortRef`, normalizes dotted (`A21.3`, `A0.3`) and FIPS (`A21I1`) input, and rejects box digits outside 1–7 (`E-NODE-01`). `idef0_core::profile::Profile` gives the profile box limit. Property tests cover round-trips and normalization; CI fixes `PROPTEST_RNG_SEED` per test job.
- CI cross-OS and MSRV (roadmap M0.4): `test (macos)` on macos-14, `test (windows, MSVC)` on windows-2022, and `msrv`, which checks the native crates on the `rust-version` from `[workspace.package]` (1.90). `.gitattributes` keeps every checkout LF.
- CI base (roadmap M0.3): `.github/workflows/ci.yml` with the `lint`, `test (linux)`, `wasm32 build` and `docs links` jobs. `deny.toml` holds the license allowlist (architecture §17.1); `scripts/check-dependency-graph.sh` is the dependency audit (architecture §2.2, §3.2), which also keeps `idef0-mangle` and `idef0-layout` independent on every target and for dev-dependencies; `scripts/check-doc-links.py` is the repo-wide link checker.
- Workspace foundation (roadmap M0.2): `[workspace.package]`, the verified
  `[workspace.dependencies]` table, workspace lints (`unsafe_code = "forbid"`),
  the pinned toolchain `1.96.0` with the `wasm32-unknown-unknown` target, and MSRV 1.90.
- Determinism lint bans for `idef0-core`, `idef0-mangle` and `idef0-layout` (hash collections,
  clock, environment, ulid/rand/getrandom entropy, `f32`/`f64` transcendental functions), with the
  negative test `scripts/check-determinism-lints.sh`, which requires every ban entry to fire.
  `idef0-wasm` bans `std::time::{Instant, SystemTime}` and refuses a wasm32 build without
  `--cfg=web_sys_unstable_apis`.
- New `idef0-ingest` crate. `idef0-server` is now a library plus a binary. The CLI binary is named `idef0`.
- `/pr-review` Claude Code skill (`.claude/skills/pr-review/`), adapted from the maintainer's review skill to this repo's checks and rules.
- v0.2 specification set, decisions D1–D20, fixtures and the FIPS PUB 183 reference copy (M0.1).

### Removed
- The M4.0 spike's prototype sizing, placement and routing (`idef0_layout::spike` keeps Auto-Arrange step 1 until M4.7); `scripts/layout-spike` now measures the real engine (ADR 0002).
- `docs/research/ierc95.pdf` (Presley & Liles). It is still cited as an informative reference, but the file is not redistributed now that the repository is public.
